# Sistema SaaS de Gestão de Administração Judicial no Brasil — Estrutura Básica, Funcionalidades Obrigatórias, Stack Técnica e Integrações

> Documento técnico preparado em 2 de maio de 2026 para advogado brasileiro (OAB/RJ) que projeta SaaS para Administradores Judiciais (Lei 11.101/2005, com redação da Lei 14.112/2020) e Administradores da Massa Insolvente Civil (CPC/1973, arts. 748–786‑A, mantidos vigentes pelo art. 1.052 do CPC/2015).

---

## TL;DR

- **Stack recomendada (2026):** Next.js 15 (App Router) + TypeScript + Tailwind/shadcn‑ui no front; **tRPC + Hono** rodando em Edge/Node como camada de API tipada; **PostgreSQL gerenciado no Supabase** (autenticação, Storage, Realtime e Row‑Level Security para multi‑tenant); **Drizzle ORM** (preferido para edge/serverless e fluxos de "vibe coding") com Prisma como alternativa para times que valorizam ecossistema mais maduro; **Inngest** ou **Trigger.dev v3** para jobs longos; **Resend** + **Twilio/Z‑API** (WhatsApp) para comunicações; **Asaas** (pagamentos PJ brasileiros, regulado pelo BACEN, código 461) para o billing do SaaS e contas da massa, com **Stripe** complementar para clientes internacionais; **Vercel AI SDK** com **Anthropic Claude Sonnet/Opus 4.x** e **GPT‑5/4o** via AI Gateway. Para **vibe coding**: prototipar UI no **Lovable** (full‑stack com Supabase nativo) → migrar para **Cursor + GitHub** para refinamento sério → deploy em **Vercel + Supabase** (com Cloudflare R2 para anexos volumosos).
- **Arquitetura:** monolito modular em Next.js com DDD aplicado ao domínio falimentar, **multi‑tenant por `tenant_id` com RLS no Postgres** (cada escritório de AJ é um tenant; cada processo é um *workspace* dentro do tenant); núcleo organizado em módulos de Cadastro, Processos, Prazos/Tarefas, Credores, Massa, Tesouraria, Realização do Ativo, AGC, Plano de RJ, Relatórios, Prestação de Contas, Comunicações/Editais, GED, Jurisprudência, IA, Portal do Credor, Portal do Devedor, BI e Admin do SaaS. Compliance LGPD (controlador/operador, DPO, base legal — art. 7º), audit log imutável, criptografia em repouso e trânsito, e logs de IA com citação obrigatória de fonte verificável (anti‑alucinação).
- **Integrações brasileiras prioritárias:** API Pública do **DataJud/CNJ** (consulta nacional via APIKey), **MNI 2.2.x** para PJe (peticionamento e consulta — cobertura desigual entre tribunais), e adaptadores para **eproc, ESAJ, Projudi, eSAJ TJSP/TJRJ**, idealmente intermediados por agregadores (Escavador, JusBrasil, Codilo, Digesto, Judit) por causa da fragmentação; **PDPJ‑Br/Jus.br** + **Domicílio Judicial Eletrônico** (Resolução CNJ 455/2022); **BrasilAPI/ViaCEP/Receita Federal**; **Asaas/Open Finance Brasil** para conta da massa; **ONR / RI Digital** (Lei 13.465/2017, Provimento CNJ 89/2019) com APIs para certidões, matrícula online, e‑Protocolo, monitor registral; **CENPROT/IEPTB**; **JUCERJA** e demais juntas via **REGIN**; **e‑Notariado/CNB**; **SCR/Bacen** (acesso indireto via instituição autorizada); **D4Sign/Clicksign/ZapSign/Autentique** + **gov.br** (assinatura ICP‑Brasil e avançada da Lei 14.063/2020); **DJEN nacional** para editais (art. 7º, §2º; art. 99 da Lei 11.101/05); leiloeiros (Sodré Santoro, Superbid, Mega Leilões, Frazão, Zukerman) — em sua maioria **sem API pública padronizada**, exigindo integração caso a caso ou via portais judiciais. **SisbaJud, RenaJud, InfoJud** são acessíveis apenas a magistrados/servidores: o sistema do AJ deve recepcionar e organizar respostas, não consultar diretamente.

## 1. Stack Técnica Recomendada

### 1.1 Visão geral e justificativa

O perfil do usuário (advogado, OAB/RJ, vibe coding) e o domínio (jurídico complexo, longa cauda regulatória, multi‑tenant, alta integração com órgãos públicos brasileiros) recomendam fortemente um stack **TypeScript ponta‑a‑ponta**, **serverless‑friendly**, com forte ecossistema de IA, componentes UI prontos e fácil reprodutibilidade em ferramentas como Lovable, v0 e Cursor. As escolhas abaixo refletem popularidade real em 2025–2026 e adequação ao perfil "solo founder + IA agente + futura equipe".

### 1.2 Frontend

| Decisão | Recomendação |
|---|---|
| Framework | **Next.js 15** (App Router, Server Components, Server Actions) |
| Linguagem | **TypeScript** estrito (`"strict": true`) |
| UI | **Tailwind CSS v4** + **shadcn/ui** (Radix + Tailwind, totalmente copiado para o repo, ideal para customização forense) |
| State client | **TanStack Query** + **Zustand** quando necessário |
| Forms | **React Hook Form** + **Zod** (mesmos schemas do back) |
| Tabelas/relatórios | **TanStack Table** + **Recharts**/**Tremor** para BI |
| i18n | `next-intl` (PT‑BR padrão; preparar EN para insolvência transnacional, art. 167‑A da Lei 11.101/05) |

Justificativa: o trinômio Next.js 15 + Tailwind + shadcn/ui é o stack canônico do Vercel, do v0 e do Lovable; a saída de um prompt em Lovable já vem nesse formato, eliminando atrito ao migrar para Cursor.

### 1.3 Backend / API

| Camada | Recomendação | Por quê |
|---|---|---|
| API tipada interna | **tRPC v11** dentro do mesmo monorepo Next.js | Type‑safety end‑to‑end sem schemas duplicados; ideal para vibe coding (o agente "vê" o tipo do backend ao gerar componente) |
| API pública/REST (portais e integrações) | **Hono** rodando como Route Handler do Next.js (ou Cloudflare Worker) | Web Standards (Request/Response), edge‑native, baixa cold start, ideal para webhooks e integrações com cartórios |
| Validação | **Zod v3+** | Idêntica entre client/server |
| Alternativas | **NestJS** (caso a equipe cresça e queira DI/módulos enterprise); **Fastify** (alta performance) | Não recomendados como ponto de partida pela curva e boilerplate |

Para um SaaS jurídico em estágio inicial com IA‑driven development, a combinação **Next.js Route Handlers + tRPC + Hono** apresenta a menor fricção. NestJS torna‑se relevante após ~50 endpoints ou quando entrar uma equipe formal.

### 1.4 Banco de dados

| Provedor | Recomendação |
|---|---|
| **Supabase** (Postgres gerenciado) | **Recomendado** — único que combina Auth, Storage, Realtime, Edge Functions, RLS nativo e ecossistema dominante em vibe coding (Lovable/Bolt usam por padrão) |
| Neon | Ótimo para serverless puro com branching de DB; mais simples mas sem Auth/Storage |
| Vercel Postgres (Neon white‑label) | Conveniente se já estiver na Vercel; perde recursos do Supabase |

Padrão: **PostgreSQL 15+** com extensões `pgcrypto`, `pg_trgm` (busca textual em peças), `uuid-ossp`, `vector` (pgvector para RAG jurisprudencial) e `pg_audit` para audit log.

### 1.5 ORM

| ORM | Recomendação |
|---|---|
| **Drizzle** | **Recomendado** para novo projeto: schema em TypeScript puro, ~7 kB, edge‑native, sem `prisma generate`, tipos instantâneos, excelente para Supabase com `prepare: false` em transaction pooling |
| Prisma 7 | Ecosistema maior, Prisma Studio, migrations declarativas; em 2025 removeu engine Rust e tornou‑se serverless‑friendly. Preferível se o time vier de Prisma ou exigir migrations geradas automaticamente |

Para "vibe coding": Drizzle vence porque o LLM vê todo o schema em TS e infere tipos sem etapa de codegen.

### 1.6 Autenticação

| Provedor | Quando usar |
|---|---|
| **Supabase Auth** | **Recomendado** se DB já é Supabase. Suporta MFA, OAuth (Google/Microsoft 365), magic link, integração nativa com RLS via `auth.uid()` |
| Clerk | Melhor UX/onboarding pronto; integra com Supabase mas adiciona vendor extra |
| Auth.js (NextAuth) | Open‑source, máxima flexibilidade; exige mais código |

**Login adicional obrigatório:** **gov.br** (OIDC) para permitir cadastro/assinatura de credores PF nos portais externos, e **certificado ICP‑Brasil A1/A3** via componente WebPKI (D4Sign/Clicksign expõem) para o AJ assinar peças.

### 1.7 Storage

| Provedor | Uso |
|---|---|
| **Supabase Storage** | Documentos do dia‑a‑dia, anexos do credor (até alguns GB) |
| **Cloudflare R2** | Arquivamento de longa duração (autos integrais, vídeos de AGC), zero egress fee — crítico em RJs com 10 mil+ credores |
| AWS S3 | Plano B para escala enterprise |

### 1.8 Filas / Jobs

| Tecnologia | Caso de uso |
|---|---|
| **Inngest** | **Recomendado** para a maioria dos workflows: serverless‑native, generoso free tier (50k execuções/mês), durable workflows para fluxos como "consultar processo no DataJud → baixar movimentações → atualizar timeline → notificar prazos" |
| Trigger.dev v3 | Jobs longos (>5 min): OCR de 10 mil páginas, geração de PDF de QGC, treinamento de embeddings jurisprudenciais; Bun‑workers, sem timeout serverless; permite self‑hosting |
| BullMQ + Redis (Upstash) | Apenas se já houver Redis e necessidade de altíssimo throughput |

### 1.9 Email, SMS e WhatsApp

- **Resend** (transacional, com React Email para templates de ofícios) — recomendado.
- **Postmark** como alternativa enterprise.
- **Twilio** ou **Z‑API** para WhatsApp Business — Z‑API tem melhor custo BR.
- **Zenvia** para SMS no Brasil.

### 1.10 Observabilidade, segurança e qualidade

- **Sentry** (erros front + back).
- **Axiom** ou **Better Stack** para logs estruturados.
- **Vercel Analytics** + **PostHog** (produto + sessão).
- **Checkly** (synthetic monitoring para integrações com tribunais — críticas).
- **Snyk** + **Dependabot** + **GitHub Advanced Security**.

### 1.11 Pagamentos

| Caso | Solução |
|---|---|
| **Billing do SaaS (assinaturas dos AJs)** | **Asaas** — instituição de pagamento e SCD autorizada pelo BACEN (código 461), PCI‑DSS, suporta PIX/boleto/cartão recorrente, NF‑e automatizada, split, antecipação. Único provedor brasileiro que oferece "Conta Digital" via API |
| Conta operacional da massa | Conta judicial (CEF/BB) + conta operacional integrada via **Asaas** ou Open Finance |
| Internacional (futuro) | **Stripe** (clientes do exterior em RJ transnacional) |
| Cobrança de credores em UPI/leilão | **Iugu**, **PagSeguro** ou Asaas para boletos |

### 1.12 IA / LLM

- **Vercel AI SDK** (unificado, suporta Anthropic, OpenAI, Google e provedores via AI Gateway).
- **Anthropic Claude Sonnet 4.5** (default — melhor para análise documental e raciocínio jurídico longo); **Claude Opus 4.6** com adaptive thinking para tarefas críticas.
- **GPT‑4o/GPT‑5** via OpenAI ou Azure (OCR + extração estruturada de balanços).
- **Google Gemini** Pro/Flash para multimodalidade (planta cadastral, fotos do auto de arrecadação).
- **pgvector** no Supabase ou **Pinecone** para RAG sobre jurisprudência.
- **Anti‑alucinação obrigatória:** toda saída da IA deve trazer (i) citação com hash do documento‑fonte, (ii) confidence score, (iii) carimbo "verificado pelo AJ" antes de produzir efeito jurídico, e (iv) gravação completa do prompt+resposta em audit log.

### 1.13 Compatibilidade com vibe coding

| Ferramenta | Adequação ao SaaS jurídico | Observações |
|---|---|---|
| **Lovable** | ⭐⭐⭐⭐⭐ MVP/prototipação | Stack default Lovable = Next.js + Supabase + shadcn — alinhado com a recomendação. Edição visual e GitHub sync. Ideal para validar telas com AJs reais antes do Cursor |
| **v0 (Vercel)** | ⭐⭐⭐⭐ Componentes pontuais | Excelente para gerar telas isoladas (formulário de habilitação, dashboard) com Tailwind/shadcn |
| **Cursor** | ⭐⭐⭐⭐⭐ Produção | IDE definitiva para refinar e manter código complexo (RLS, integrações, IA) |
| **Bolt.new** | ⭐⭐⭐ Demos rápidas | Browser‑based; útil para protótipos descartáveis; menos previsível em produção |
| **Replit Agent 3** | ⭐⭐⭐ Full‑stack autônomo | Boa para integrar Stripe/Asaas e deploy em uma só plataforma; custo pode escalar |
| **Windsurf** | ⭐⭐⭐⭐ Alternativa ao Cursor | Cascade para tarefas multi‑arquivo |
| **Claude Code (Anthropic)** | ⭐⭐⭐⭐⭐ Refactor/agents | Excelente para tarefas multi‑arquivo, geração de migrations Drizzle e revisões jurídicas |
| Aider | ⭐⭐⭐ CLI | Para times técnicos que preferem terminal |

**Fluxo recomendado (vibe coding jurídico):**
1. **Lovable** — prototipar fluxos críticos (cadastro de processo, habilitação de crédito, AGC) com Supabase real.
2. Conectar **GitHub** (sync bidirecional) e migrar para **Cursor + Claude Code** assim que o app passar de ~30 telas.
3. **Vercel** para deploy front + Route Handlers; **Supabase Cloud** para DB/Auth/Storage; **Cloudflare R2** para arquivos pesados; **Inngest Cloud** para jobs.
4. Templates de partida: **T3 Stack** (`create-t3-app`) com Drizzle, ou os starters oficiais do Supabase para Next.js.

## 2. Arquitetura do Sistema

### 2.1 Padrão arquitetural

**Monolito modular em Next.js (modular monolith)**, organizado por *bounded contexts* do DDD, com separação clara de:

- **Apresentação** — `app/` (Next.js App Router), Server Components.
- **Aplicação** — casos de uso (`/use-cases`), orquestração de regras.
- **Domínio** — entidades, agregados, eventos de domínio (`Crédito`, `MassaFalida`, `Plano`, `AGC`).
- **Infraestrutura** — repositories Drizzle, clients (DataJud, MNI, Asaas, e‑mails), filas Inngest.

Microserviços só se justificam após PMF e escala >10 mil processos ativos. Antes disso, o overhead operacional é desproporcional.

### 2.2 Bounded contexts mapeados ao domínio falimentar

1. **Identity & Access** (Tenant, User, Role, Permission).
2. **Case Management** (Processo, Fase, Evento, Timeline).
3. **Creditor Verification** (Credor, Crédito, Habilitação, Divergência, Impugnação, QGC).
4. **Estate Management** (Inventário, Bem, Avaliação, Restituição).
5. **Treasury** (Conta da Massa, Lançamento, Conciliação, Ordem de Pagamento art. 83/84).
6. **Asset Realization** (Plano de Venda, Edital, Praça, Arrematação).
7. **Creditors' Assembly** (AGC, Convocação, Procuração, Voto, Quórum, Ata).
8. **Recovery Plan** (Plano de RJ, Cumprimento, Supervisão 2 anos do art. 61).
9. **Reporting** (RAM, Relatório do art. 22 III "e", Relatório Final art. 155, Prestação de Contas).
10. **Communications** (Ofícios, Editais DJEN, e‑mails, WhatsApp).
11. **Document** (GED, OCR, classificação).
12. **Knowledge** (Jurisprudência STF/STJ, normativos CNJ, doutrina).
13. **AI Assistance** (orquestrador de LLM com guard‑rails e citation enforcement).
14. **External Portals** (Credor, Devedor).
15. **Analytics & BI**.
16. **SaaS Admin** (tenants, billing, suporte).

### 2.3 Multi‑tenancy

**Padrão recomendado: shared schema + `tenant_id` + Postgres Row‑Level Security (RLS).**

- Toda tabela transacional tem `tenant_id UUID NOT NULL`.
- Cada `Case` (processo) tem também `case_id` (workspace).
- **Policies RLS** filtram automaticamente: `USING (tenant_id = auth.tenant_id())` via JWT custom claim.
- Casos sensíveis (insolvência transnacional, segredo de justiça) usam **schema dedicado** ou banco separado por contrato premium.
- **Service role key** somente em jobs server‑side, jamais exposta ao client; uso explícito e auditado.
- Pitfall conhecido: views por padrão burlam RLS; usar `security_invoker = true` (Postgres 15+) ou esquema não exposto.

### 2.4 Estratégia de testes

| Camada | Ferramenta | Cobertura mínima |
|---|---|---|
| Unit | **Vitest** | 80% domínio + use‑cases |
| Integration | Vitest + DB de teste (Supabase local via Docker) | Repositories + RLS policies |
| E2E | **Playwright** | Fluxos críticos: novo processo, habilitação, AGC, fechamento de mês |
| Contratos | **Pact** ou OpenAPI snapshots | Integrações DataJud/MNI/Asaas |
| RLS | Testes específicos com diferentes JWTs simulados | Cobertura 100% de tabelas com tenant_id |
| Acessibilidade | axe-core no Playwright | WCAG 2.2 AA (Resolução CNJ 401/2021 sobre acessibilidade) |

### 2.5 CI/CD

- **GitHub Actions** com matriz: lint (Biome ou ESLint), typecheck, vitest, playwright, build.
- **Preview deployments** automáticos no Vercel para cada PR.
- **Migrations** Drizzle aplicadas em staging via job pós‑merge; produção em janela controlada.
- **Feature flags** (Vercel Edge Config ou Statsig) para liberar módulos por tenant.
- **Backups** automáticos do Supabase + snapshots do R2 + replicação cross‑region (DR).

### 2.6 Estratégia de deploy

- **Vercel** para front + Route Handlers + Edge Functions.
- **Supabase Cloud** (região São Paulo — `gru1`) para DB/Auth/Storage.
- **Inngest Cloud** ou **Trigger.dev Cloud** para workflows.
- **Cloudflare R2** para arquivos.
- **DNS no Cloudflare** + **Cloudflare WAF** para portais externos (proteção contra abuso por credores).

## 3. Módulos Funcionais Obrigatórios

> Para cada módulo: **MVP** (fase 1, indispensável) | **V1‑V2** (desejável, expansão) | **V3+** (avançado).
> A numeração das funcionalidades é normativa para fim de roadmap.

### A. Cadastro e Configuração

**MVP**
1. Cadastro do escritório/AJ (PF ou PJ) com CNPJ/CPF, endereço, dados bancários, OAB, certidões de regularidade junto ao órgão de classe (Resolução CNJ 393/2021, art. 4º).
2. Cadastro de equipe com **RBAC granular** (sócio, advogado, contador interno, assistente, estagiário, auditor externo); permissões por módulo + ação + tenant.
3. Cadastro de auxiliares externos (leiloeiros, peritos, contadores, avaliadores) com vínculo a processo.
4. Configurações de tribunal padrão por comarca, modelos de documento, marca branca (logo, cores) para portais externos.
5. Política de retenção e classificação de documentos (LGPD).

**V1‑V2**
6. Suporte multi‑escritório (matriz/filial) e cooperação entre AJs.
7. Cadastro de marketplace de auxiliares (busca de leiloeiros credenciados etc.).

### B. Processos (Cases)

**MVP**
1. Cadastro com tipo: **Falência**, **RJ ordinária**, **RJ ME‑EPP** (art. 70‑A), **Recuperação Extrajudicial** (art. 161), **Insolvência Civil** (CPC/73 art. 748+).
2. **Triagem inicial** — wizard que classifica devedor empresário (art. 966 CC) → Lei 11.101 vs. devedor civil → CPC/73 + arts. 955‑965 CC.
3. Vinculação de partes: devedor, credores, juízo, MP, Fazenda, comitê.
4. **Linha do tempo** (timeline) com todos os eventos automáticos e manuais.
5. Gestão de despachos, decisões, sentenças com upload + OCR.
6. **Controle de fases** processuais conforme catálogo do prompt mestre (deferimento, fase administrativa do art. 7º, plano, AGC, supervisão, encerramento).
7. Importação de processos por número CNJ (DataJud) ou OAB.

**V1‑V2**
8. Detecção automática de movimentações relevantes (LLM classifica push do tribunal).
9. Insolvência transnacional (Capítulo VI‑A, arts. 167‑A a 167‑Y, Resolução CNJ 394/2021).
10. Cooperação direta com juízos estrangeiros (UNCITRAL Model Law).

### C. Prazos e Tarefas

**MVP**
1. Calendário com prazos legais e judiciais; integração Google Calendar / Microsoft 365 (CalDAV).
2. **Engine de regras de geração automática** a partir de eventos‑gatilho. Exemplos canônicos:
   - Decretação de falência → criar tarefas de comunicações obrigatórias (RFB, INSS, JUCESP/JUCERJA, ONR, CENPROT) em D+5; arrecadação em D+15; auto de arrecadação; venda em D+180 (art. 22, III, "j").
   - Deferimento de RJ → publicação edital art. 52 §1º; **prazo de 15 dias** para credores apresentarem habilitações ao AJ (art. 7º, §1º); **prazo de 45 dias** para AJ publicar lista do art. 7º, §2º; **60 dias** para devedor apresentar plano (art. 53); AGC em até 150 dias (art. 56, §1º); supervisão por 2 anos (art. 61).
   - Aprovação do plano → rotina de monitoramento mensal art. 22, II, "c"+"h".
3. Alertas multicanal (e‑mail, push web, **WhatsApp via Z‑API**, dashboard).
4. Atribuição de responsável e workflow de aprovação interna.
5. **Risco operacional** classificado em BAIXO/MEDIO/ALTO/CRITICO baseado em (i) prazo restante, (ii) impacto (destituição vs. simples ofício), (iii) presença de crédito ≥ R$ 1 mi, (iv) atos do art. 64.
6. SLA por tipo de tarefa; mural de prazos vencendo nas próximas 72h.

**V1‑V2**
7. Sugestão de redistribuição de carga via IA quando equipe estiver sobrecarregada.
8. Templates de checklist (Diligência inicial pós‑decretação, Pré‑AGC).

### D. Credores e Verificação de Créditos

**MVP**
1. Cadastro de credores PF/PJ com qualificação completa (CPF/CNPJ via BrasilAPI/Receita), endereço (ViaCEP), conta bancária, e‑mail, procuradores.
2. Habilitação de créditos com upload de documentos (contratos, notas fiscais, CCBs, sentenças trabalhistas).
3. Análise documental com OCR + sugestão de classificação por IA (com revisão humana obrigatória).
4. **Classificação conforme art. 83 da Lei 11.101/05 (com redação da Lei 14.112/2020):**
   - I — Trabalhistas (limitados a 150 SM/credor) e acidentes do trabalho;
   - II — Garantia real (limitada ao valor do bem);
   - III — Tributários, exceto extraconcursais e multas;
   - VI — Quirografários (incluindo saldos não cobertos e créditos antes "com privilégio especial/geral", revogados pela 14.112);
   - VII — Multas contratuais e penas pecuniárias (inclui multas tributárias);
   - VIII — Subordinados (lei/contrato; sócios/administradores sem vínculo empregatício; em condições não comutativas);
   - IX — Juros vencidos após decretação;
   - **Extraconcursais (art. 84)** com sub‑hierarquia I‑A a I‑E (incluindo DIP financing, restituições do art. 86, honorários do AJ relativos à massa, créditos trabalhistas pós‑falência, atos da RJ art. 67).
   - **ME‑EPP** com regra própria (art. 41, IV);
   - **Trabalhistas** verificados via Justiça do Trabalho (art. 6º, §2º).
5. **Geração automática da lista do art. 7º, §2º** (segundo edital) a partir do passivo do devedor + habilitações/divergências.
6. Impugnações e divergências com autuação separada (art. 8º).
7. **QGC — Quadro Geral de Credores** consolidado (art. 18) assinado pelo juiz e AJ.
8. **Insolvência civil:** classificação conforme **CC arts. 955‑965** (privilégio geral, especial, e quirografário) — *engine separada*.
9. **Portal do Credor** (ver módulo P) com login gov.br, autoatendimento de habilitação e acompanhamento.
10. Importação em lote de credores via planilha + validação assistida por IA.

**V1‑V2**
11. Reconciliação automática com a contabilidade da devedora (entrada por SPED/ECD).
12. Detecção de duplicidades por similaridade (mesmo crédito habilitado por cessionário e cedente).
13. Workflow de cessão de crédito (art. 83, §5º — créditos cedidos preservam natureza).
14. Incidente de classificação de crédito público (art. 7º‑A) — fluxo Fazenda Pública 30 dias.

### E. Massa Falida / Massa Insolvente

**MVP**
1. **Inventário de bens** (móveis, imóveis, semoventes, intangíveis, créditos a receber, participações societárias, ativos digitais, criptoativos).
2. Avaliação com laudo (valor de mercado, valor de liquidação, data de avaliação, perito responsável).

### F. Financeiro / Tesouraria da Massa

```
Tenant(id, name, document, plan, billing_status)
User(id, tenant_id, email, role, oab_number, profile)
Role(id, name) ; Permission(id, code) ; RolePermission(role_id, permission_id)

Case(id, tenant_id, type[FALENCIA|RJ|RJ_MEEPP|REXT|INSOLV_CIV],
     court, judge, case_number_cnj, debtor_party_id, status, phase,
```

## 6. Segurança e Compliance

### 6.1 LGPD (Lei 13.709/2018)

- Mapeamento de tratamento por finalidade (cadastro, cobrança, comunicação processual, IA).
- **Bases legais**: cumprimento de obrigação legal/regulatória pelo controlador (Lei 11.101/05); execução de contrato (clientes do SaaS); legítimo interesse (segurança); consentimento (marketing).
- Papel do escritório de AJ: **controlador**; SaaS: **operador**.
- **DPO** designado e divulgado; canal de titular.
- **Registro de operações de tratamento** (ROPA).
- Termos de Uso e Política de Privacidade do SaaS específicos para sigilo profissional do advogado (art. 7º, II do Estatuto da OAB).

### 6.2 Sigilo profissional e Marco Civil

- Garantia contratual de sigilo (cláusula no MSA com tenants).
- Logs e dados em datacenter brasileiro (Supabase região São Paulo) preferencialmente.
- Não permitir acesso de equipe do SaaS a dados do tenant exceto sob ticket assinado com motivo.

### 6.3 Boas práticas técnicas

- Criptografia em repouso (Supabase usa AES‑256) e em trânsito (TLS 1.3).
- Rotação de keys (KMS) trimestral.
- **Audit log imutável com hash chain** atendendo Resolução CNJ 522/2023 sobre Modelo de Requisitos para Sistemas de Gestão de Documentos Judiciais.
- **Backups** (PITR Supabase + snapshots R2 cross‑region) com testes de restore mensais.
- **DR**: RPO 1h, RTO 4h.
- Alinhamento a controles **ISO 27001** (Anexo A) e **SOC 2 Type II** (alvo no V2).
- Segurança de aplicação: SAST (Semgrep), SCA (Snyk), DAST (OWASP ZAP), pentest anual.

### 6.4 Resoluções CNJ aplicáveis (verificar publicação atualizada)

- Resolução CNJ **331/2020** (DataJud) e Portaria 160/2020.
- Resolução CNJ **335/2020** (PDPJ‑Br).
- Resolução CNJ **393/2021** (Cadastro de AJs nos TJs).
- Resolução CNJ **394/2021** (insolvência transnacional — cooperação direta).
- Resolução CNJ **455/2022** (PSPJ, DJEN, Domicílio Judicial Eletrônico).
- Resolução CNJ **466/2022** (Fonaref).
- Resolução CNJ **522/2023** (Modelo de Requisitos para Sistemas de Gestão).
- Recomendações **72/2020** (RAM, Anexos I‑V), **103/2021** (documentos para RJ), **109/2021** (comunicação de distribuição), **110/2021** (AGC virtual/híbrida) e **141/2023** (honorários do AJ).
- Provimentos da CGJ/RJ: confirmar localmente; o **Provimento CGJ/RJ 32/2017** (e atualizações) regula procedimentos cartoriais — **verificar**.

### 6.5 LGPD aplicada a IA

- Banimento de uso de dados sensíveis para treino sem consentimento.
- Anti‑alucinação obrigatória; logs por 5 anos.
- Avaliação de impacto (DPIA) por funcionalidade de IA antes do GA.

## 8. Riscos e Desafios

| Categoria | Risco | Mitigação |
|---|---|---|
| **Regulatório** | Ausência de norma técnica oficial para SaaS de AJ; mudanças por novas Recomendações do CNJ ou reforma adicional da Lei 11.101 | Acompanhar Fonaref (Resolução 466/2022); arquitetura modular para absorver mudanças; comitê interno jurídico‑técnico |
| **Integração** | APIs de tribunais instáveis ou inexistentes; MNI com cobertura desigual; eSAJ/Projudi sem API — **risco real e documentado** | Fallback para agregadores comerciais (Escavador, Judit); contratos com SLA; cache + retry exponencial; observabilidade (Checkly) |
| **Adoção** | AJs conservadores; resistência a novo software; OAB/RJ sem padrão | Co‑design com 3‑5 AJs early adopters; importação de Excel/Word legados; treinamento e materiais |
| **Performance** | RJs com 50 mil+ credores; OCR de 100 mil páginas; AGC ao vivo com 5 mil pessoas | Plano de carga; CDN; jobs longos no Trigger.dev; Postgres com partitioning por tenant |
| **Compliance/LGPD** | Vazamento de dado processual (sigilo) | RLS + audit log + DPO; pen‑test anual; cláusula de SLA com cliente |
| **IA / Alucinação** | LLM gerar classificação errada de crédito | Sempre rascunho; flag "Sugestão IA"; obrigatoriedade de revisão humana antes de qualquer submissão; logs imutáveis |
| **Concorrência** | Astrea, Projuris, ADVBox dominam software jurídico geral; AJUD e específicos para AJs | Nicho fundo (somente AJ + insolvência civil); profundidade > largura; integrações exclusivas (DataJud + ONR + CENPROT + Asaas) |
| **Conta da massa** | Bancos comerciais relutam em abrir conta para massa falida | Parcerias com Asaas (SCD/IP autorizada BACEN), Inter, Cora |
| **Continuidade do negócio** | Indisponibilidade de Vercel/Supabase | Multi‑cloud (Vercel + Cloudflare + AWS) no V3; backups cross‑provider; runbook de DR |

### 10.2 Recomendação final — fluxo de produção

1. **Design e prototipação** no **Lovable** com Supabase real (cria os módulos A–D do MVP em 1–2 semanas com prompts bem escritos).
2. **GitHub sync bidirecional** ativo desde o dia 1.
3. Quando a complexidade de RLS, integrações (DataJud/MNI/Asaas) e jobs entrar em cena, mover desenvolvimento para **Cursor + Claude Code**, com Lovable usado para tarefas pontuais de UI.
4. **Testing/QA** com Playwright dentro do Cursor; CI no GitHub Actions.
5. **Deploy**: Vercel (front + Route Handlers), Supabase (DB/Auth/Storage), Cloudflare R2, Inngest, Resend, Asaas.
6. **Observabilidade**: Sentry + PostHog + Better Stack desde a primeira release.

- `create-t3-app` (Next.js + tRPC + Drizzle + NextAuth) — base sólida.
- **Supabase Next.js Starter** (oficial) — para começar com Auth + RLS prontos.

## Caveats e Avisos Finais

- **Recomendações CNJ não têm força normativa cogente** (STF, MS 39.412/DF, decisão monocrática do Min. Luiz Fux, 1/2/2024 — citada em literatura especializada): elas são diretrizes mínimas; o sistema deve permitir parametrizar por comarca/juízo conforme entendimentos locais.
- **MNI / PJe / eSAJ**: a integração depende de cada tribunal e pode quebrar; manter monitoramento ativo (Checkly) e canal direto com áreas de TI dos TJs/TRFs.
- **Provimentos da CGJ/RJ aplicáveis ao Rio de Janeiro** devem ser conferidos diretamente no portal `tjrj.jus.br/corregedoria` antes do lançamento — texto desta pesquisa cita‑os como "verificar".
- **APIs de SCR/CCS, e‑CAC, INSS** são restritas: não há acesso programático direto pelo AJ; o sistema deve organizar consultas manuais (via Registrato gov.br do titular ou via instituição financeira parceira).
- **SisbaJud/RenaJud/InfoJud** são exclusivos do Poder Judiciário: o SaaS não consulta diretamente; recebe e organiza respostas do PJe.
- **Plataformas de leilão**: a maioria dos grandes leiloeiros não possui API pública aberta; planejar integração caso a caso e pacote padronizado de edital/lotes.
- **Recomendação CNJ 110/2021** estabelece requisitos para AGC virtual/híbrida, mas tem caráter recomendatório; a Lei 14.112/2020 introduziu base legal explícita para votação eletrônica (art. 39, §4º, II).
- **Multas tributárias**: classificação no inciso VII do art. 83 (não mais III) — atenção à atualização da Lei 14.112/2020 nas regras do sistema.
- **Insolvência civil** segue regida pelo CPC/1973 (arts. 748 a 786‑A) por força do art. 1.052 do CPC/2015 enquanto não houver lei específica; o sistema deve manter motor separado e jurisprudência específica.
- **Custo dos LLMs**: monitorar tokens por tenant; pacote do plano deve cobrir uso médio; cobrança variável para uso extra.
- **Concorrência**: AJs grandes tendem a desenvolver internamente — ofertar API e white‑label como diferencial.
- **Insolvência transnacional**: respeitar a Resolução CNJ 394/2021 e os arts. 167‑A a 167‑Y — funcionalidade específica do V2/V3.

> **Nota metodológica**: este relatório foi produzido a partir de fontes oficiais (planalto.gov.br, cnj.jus.br, gov.br, bcb.gov.br, registrodeimoveis.org.br, pdpj.jus.br, datajud-wiki.cnj.jus.br) e literatura especializada (Migalhas, ConJur, JOTA). Sempre que um nome de Resolução, Súmula ou Tema STJ não pôde ser confirmado em fonte oficial, foi marcado com "verificar". Os parágrafos sobre integrações com tribunais refletem o estado conhecido do MNI/PJe em 2025–2026, com a ressalva de cobertura desigual entre tribunais.
